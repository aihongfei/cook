四块的来历（为什么是它们）

  • ② 时令精选：全项目唯一带"时令"的是厨房页底部那张静态图片（字都烘焙在图里、四季不变、不可点）。所以这里给的是真入口：38 道秋菜、点得进详情。它回答的是"这个季节有什么"，与「摇一桌」（配这一餐）、「帮我决定」（挑一道）不是同一个问题。
  • A 家庭月报：「我的」页只有你个人的打卡热力图与我的菜数，「家人最爱」是菜榜单——全家这个月过得怎么样没人讲。四个数全是库里现成的（本月餐次 + 状态 + 点过的菜 + 打卡），不需要新数据。

③ 场景入口去哪了：**收进「帮我决定」抽屉**（用户 2026-10-16 的决定）

  • 用户当时问：「"今天想吃什么感觉的"和 ai 帮决定是不是重复了」——确实像。它俩都在回答"我想不出吃什么"，而那一行大字标题本来就是「今天吃什么？」；2026-10-13 已经有过一次同类合并（「帮我决定」与「AI 帮你想」两个"我替你决定"收进一个抽屉，见 D-061）。
  • 但两者不是同一件事：抽屉里给的是一道（点「就它了」就进菜单），场景词给的是一批（要自己逛）。所以合并的方向不是删掉，而是把场合变成抽屉里的一个可选条件：默认不问场合，想收窄的时候点一下。
  • 合并不只是少一块：`decide` 原先只读冰箱 / 口味 / 做过的菜，它不知道场合。这行胶囊给了它一个新维度——而因为是可选参数，默认那条路（毫秒级、纯规则、不依赖 AI）一个字没变。
  • 代价写清：`/discover/decide` 加一个可选参数（`occasion`，精确标签过滤，约 10 行 + 测试）；抽屉里多一行胶囊（73px，页面高度 0）。

一个差错：**「早上吃什么」不能留**（这一版才发现的）

  • 上一版那四个词里有「早上」，对应标签「早餐」83 道。但这一版的餐次**只有午饭与晚饭**（`MealSlot = LUNCH | DINNER`，见 `services/api/prisma/schema.prisma`）：用户在抽屉里点「早上」，`decide` 会挑出一道包子/粥，接着点「就它了」……它被加进了晚饭。这是硬错，不是口味问题。
  • 换成了「做给孩子」（儿童 33 道）——同样是个真场合，也落在午饭/晚饭里。另外三个（不想费劲 74 / 干饭要香 46 / 来客人了 33）都成立。
  • 数字都够（最少的 33 道）：不会有"点了是空的"。真一道都挑不出来时（比如冰箱与口味把这一类排空了）后端给一句话说明，不给一道编的。

季节与场合都按**标签精确取**，不靠搜索兜

  • 给菜谱查询加一个 `tag` 参数（精确匹配标签数组，可逗号给多个＝"其中一个命中"，最多 5 个）。季节与场合都走它，不用 `q`：`q` 走的是 `searchText contains`（菜名 + 别名 + 标签 + 食材名拼一起），判据是"文本里出现过这两个字"。
  • 诚实说一句：这两者眼下返回的是同一批菜。2026-10-16 把四个季节逐个 id 比过——春 21 / 夏 81 / 秋 38 / 冬 50，搜索与标签并集一个不差。所以这一条不是"现在有 bug 要修"，而是"接线要接在稳定判据上"：库里哪天出现一道名字带"夏"的凉糕却没打季节标签，搜索就会把它算进「夏日时令」那个数字里。
  • 真正的差别在"几个标签"上，而且很大：只取最正的那个标签 vs 并集 —— 春 20→21、夏 51→81、秋 35→38、冬 47→50。夏天少掉 30 道不是小数。库里同一个季节有两套叫法（「夏季」+「夏季菜谱」+「夏季养生」+「夏季饮食」），所以 `tag` 必须支持多个标签（并集，不是交集）。
  • 反过来也说明搜索不够用：那 3 道打了「秋季养生」的菜（猪肉萝卜灌汤包、红枣发糕、花生红枣焖猪手）名字里一个"秋"字都没有——搜索永远找不到它们。

「翻牌子」去哪了：**用户看完预览后定「不要翻牌子了」**（2026-10-16）

  • 它是这一批里唯一**凭好玩**才成立的块：翻菜收着，收下的进「家人最爱」。 形态（按钮版 / 滑动版）当时都做出来了，用户看过之后决定不做——那一整天的工作里这是唯一被砍掉的一块。
  • 所以这一份预览里**没有它**：页面高度按两块算（时令 157 + 家人最爱 + 月报 156）。 接口与组件都没写进代码，只有这份记录与 D-108 里留着它的来龙去脉。
  • 顺带说清它对「家人最爱」的影响：那一块在**新家庭**是空态（用户定的「没有最爱就是没有」）。 翻牌子原本是给新家庭"玩着玩着就有了信号"的那条路，砍掉之后新家庭就靠时令与月报慢慢长—— 这是用户明确选择的结果，不是遗漏。

「新家庭」那一档（切右上角那个开关看）

  • 家人最爱：只留那句空态（你 2026-10-16 定的「没有最爱就是没有」）——不塞推荐填坑；
  • 家庭月报：本月不足 3 顿时整块不画（1 顿就报"一起吃了 1 顿"没有意义，还显得这一家冷清）；
  • 时令精选照常都在——它不依赖历史，新家庭打开也有东西可看；等有过几顿饭，月报自己就长出来了（≥3 顿才画）。

刻意不做的

  • 不加回「本周菜单」（2026-10-16 刚删，理由没变：同一份安排的第三份只读副本）；
  • 不做"开头菜"（你 2026-10-16 定：「没有最爱就是没有」）——新家庭那块就是一句空态，不塞推荐填坑；
  • 不做天气推荐：现在没接任何天气源，为一个模块引一个外部依赖不划算；时令用日期就能算，先做它；
  • 月报不给谁打分：不写"谁做得最多"，家庭里这种事容易变成比较；只写全家一起的数；
  • 不给「早餐」单独开一档：要开就得先有早餐这个餐次（`MealSlot` 只有两个值），那是另一件事，不塞进这一次。
