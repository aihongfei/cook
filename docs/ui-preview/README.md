## 排版规范（落地后逐条补充）

- **按钮文案永不换行**（用户 2026-10-12 指出）：本应用的按钮都是 2–5 个字的短标签，被压窄成两行会让整行排版歪掉。已在 `apps/mobile/src/styles/index.scss` 的 `button` 基础样式里统一 `white-space: nowrap`。
  - 按钮旁边放长文本（昵称 / 邮箱 / 家庭名）时，**让文本去换行或截断，而不是压窄按钮**：文本容器要写 `min-width: 0`（flex 子项默认是 `min-width: auto`，长串会把按钮挤扁），`.btn-ghost` 这类胶囊按钮加 `flex: 0 0 auto`。
  - **没有词边界的长串（账号、邮箱）不换行、改用单行省略号**：换行会断成 `…example.co` / `m`，比截断更难看；完整值在编辑表单里看得到。
  - 实例：`/mine` 的「编辑资料」曾被长邮箱挤成 62×48（两行），修复后 69×32（一行）。
- **卡片里的横向列表要换行，不要横向滚动**（用户 2026-10-12 指出「头像列表右侧溢出了」）：
  - 现象：`/mine` 编辑资料与 `/register` 的头像选择器是 `overflow-x: auto` + `nowrap` 的一行，**滚动条被藏掉了**。8 个 38px 头像 = 353px，而卡片内宽只有 330/322px，于是整行顶出卡片右内边距、最后一个头像贴到屏幕边缘 6px。藏掉滚动条的横滚等于把内容藏起来，用户看不出还能滑，只觉得"溢出/被切了"。
  - 根因还是 flex 的 `min-width: auto`：这一行是 column flex 卡片里的**子项**，`nowrap` 让它的 min-content 等于全部头像的总宽，于是它收不到卡片宽度，只能溢出去。这与上一条「压窄按钮」是同一个规则的两个方向——那边不该缩，这边不该滚。
  - 做法：`flex-wrap: wrap`（放不下就多一行，永远不溢出）+ 把尺寸调到当前数量能排进一行（头像 35px、间距 5px → 8 个共 315px ≤ 卡片内宽 322/330），并去掉 `overflow-x: auto` 与藏滚动条的那两段 CSS。数量再多只是多一行。
  - 验收方式：在真实页面量 `row.scrollWidth === row.clientWidth`（无隐藏横滚）、`row.right <= 卡片内右缘`、每个元素都落在视口内。jsdom 没有布局，这类问题**单测测不出来**，只能靠浏览器实测量。
  - 顺带说明：`.chips`（菜谱筛选）、`.cats`（分类）、`.dish-row`（菜品卡）仍是横向滚动，那是**刻意的滑动列表**（全宽、贴页边、最后一格露半个本身是"可以滑"的提示），与卡片内的头像选择器不是一回事，未改动。
- **块下方的说明文字（tip）与上下各留同一个间隙**（用户 2026-10-12 指出）：家庭页两条说明曾出现「上 12px / 下 30px」和「上 0px / 下 35px」两种不一样的结果。
  - 根因是**相邻块的外边距会合并**（取较大者），间隙随邻居是卡片、章节标题还是按钮而变；做法是用 `.block-with-tip`（flex column + `gap: 12px`）把「块 + 说明」包起来，**间隙由容器给定**，不受合并与邻居影响。
  - 放在这个容器里的块与说明要在页面样式里显式 `margin: 0`（页面样式在组件样式之后加载，同类选择器会覆盖容器的清零规则），紧跟其后的元素也清零上外边距，让容器统管下方间距。
  - 实例：家庭页两条说明最终为「上 10px / 下 10px」（10 比块间距的 12 略紧，才像"贴在自己块下面"的附注；用户随后指出 12 仍偏大）。
  - 紧跟其后的**章节标题要收掉自己的 20px 上内边距**（`.block-with-tip + .section-title`），否则说明下方会空出一大截。
- **一句话的结果提示用 toast，不在页面里插提示段落**（用户 2026-10-12 要求）：组件 `components/ui/toast.tsx`，用法 `toast.success('邀请码已复制')` / `toast.error(apiErrorMessage(err))`。
  - 段落式提示会把下方内容顶下去、页脚跟着跳；toast 悬浮在底部 Tab 栏上方（`--spacing-tabbar` + 16px），不参与布局。
  - 语气两档：成功（米色纸片 + 品牌色「✓」）2.2 秒、失败（砖红字 + 「!」）3.6 秒；同一条文案不堆叠，点一下即散。
  - 语义：成功 `role="status"`、失败 `role="alert"`；容器不吃点击（`pointer-events: none`），不挡下面的按钮。
  - `antd-mobile` 的 Toast 包装（原 `feedback.ts` 的 `toast`/`toastSuccess`）已删除——样式与手绘风不搭，且与本组件重复。
- **不可逆或影响别人的操作必须二次确认，且用居中的模态框**（用户 2026-10-12 要求）：组件 `components/ui/ConfirmDialog.tsx`。
  - 目前用于：**退出/解散家庭、移出成员、转让掌勺人**（前两者影响自己与别人，第三者会当场把自己的管理身份交出去）。普通角色调整（改帮厨/吃货）不打扰用户，直接生效。
  - 为什么居中而不是像 toast 那样贴在底部：模态框是"必须回应才能继续"的东西，居中更能让人停下来看一眼后果。
  - 固定的几条口径：遮罩点击与 Esc 都算**取消**（永远不会因为误触而确认）；打开时焦点落在「取消」上（键盘连按回车不会误执行）；打开期间锁住背景滚动；危险操作的确认键用砖红（`.confirm__btn--danger`），与普通确认区分；请求进行中两个键都禁用（避免重复提交）。
  - 页面里不要再自己写"再想想/确定"的页内确认区（家庭页曾这么做过，已统一到弹窗）。
- **`className` 里拼条件类名，两个 class 之间必须留空格**（2026-10-12 连踩两次）：
  - 错误写法 `` className={`family-switch${on ? 'is-on' : ''}`} `` 会拼成 **`family-switchis-on`** —— 一个不存在的类名。后果比"少个修饰类"严重得多：**基础类的样式整块失效**。共享开关因此丢了 `position: relative`，里面绝对定位的白色圆点失去定位父级，飘到视口左上角 (3px, 3px) 变成一个莫名的白圈（用户截图报来）；确认弹窗那次则是砖红确认键变成普通色。
  - 安全写法：`className={['family-switch', on && 'is-on'].filter(Boolean).join(' ')}`（数组拼接）；或把空格写进条件串里 `` `${a}${on ? ' is-on' : ''}` ``（项目里 `Chips`/`MinePage`/`OrderPage` 用的是这种）。**优先数组拼接**——分隔符不落在字符串字面量里，格式化工具重排不会丢，diff 里也看得见。
  - 配套要求：**条件类名要有测试断言**。只断言 `aria-checked` 与文案发现不了（交互与语义都对，坏的只有视觉），要直接断言 `classList.contains('family-switch')` 与 `classList.contains('is-on')`。家庭页那两条用例就是这么加的，并验证过"把 bug 放回去确实会失败"。
- **抽屉/弹层不做"打开时清状态"的 effect**（2026-10-12 定，两个抽屉都照此实现）：
  - 曾经写过 `useEffect(() => { if (!visible) return; setPreview(null); setNote(''); setMealKey(preset) }, [visible, preset])`。问题：① 多一次渲染（打开瞬间先闪一下上次的残留值）；② 异步来的 options 要额外处理时序；③ oxlint 的 `react(set-state-in-effect)` 会拦。
  - 现在的做法：**状态只在首次挂载时按 props 初始化，每次打开由调用方换 `key` 让它重挂载**（`OrderDishSheet` 由 `RecipeDetailPage` 用 `orderSheetSeq` 换 key，`CheckInUploadSheet` 由 `CheckInPage` 用 `uploadSeq` 换 key）。调用方若是条件渲染（`{open && <Sheet …/>}`），本身就已经是"每次打开都是新的"。
  - 配套要求：**要有一条"关掉再开是干净的一份"的用例**，否则以后有人把 `key` 删了不会有任何测试报警。打卡抽屉那条用例验证过"去掉 key 确实会失败"。
- **"浏览器能力"类改动必须有一次真实浏览器/真机实测**（2026-10-12 定，见 `RISKS.md` R-21）：jsdom 不解码图片、不实现 canvas，单测会**静默走降级分支**而看起来"通过"。打卡缩图那条链路在单测里全是假 `Image`/假 canvas；真实数值（2400×1600 → 1600×1067 / 43KB）是在浏览器里测的。
- **二级页的返回入口由 `.page-back` 自带栏距，页面容器不再各写各的**（2026-10-12 统一，用户报"所有页面位置要统一"）：
  - 病灶：`.page-back` 只有 `padding: 8px 0`（没有左右），栏距靠各页面容器给——带栏距的容器（`.recipes-page`）里是 16px，不带栏距的（`.pscreen`）里就贴到屏幕边（打卡墙的返回键实测 x=0，其他页面 x=16），用户一眼就看出来不齐。
  - 做法：`.page-back` 自带 `padding: 8px var(--spacing-page)`；容器**已经**有栏距的场景（菜谱列表/详情）在自己样式里抵消一次：`.recipes-page .page-back { padding-left: 0 }`。家庭页原先用行内 `style={{ paddingInline: … }}` 对齐，已删掉——行内样式散在各处，正是"位置不统一"的土壤。
  - 实测口径：四个二级页（家庭、菜谱列表、菜谱详情、打卡墙）用 Range 量**文字盒子**的左缘与上缘，全部落在 x=16 / y=29。
- **同一含义的数字，一屏只出现一次**（2026-10-12，用户报"3 处张数保留一个就行"）：
  - "我的打卡"那块曾同时挂着「共 N 张」（标题行）、「N 天有打卡 · 共 M 张」（热力图图例）、「全家一起攒了 M 张」（底下一行）——三个数字相互对照，用户会去核对差在哪，反而更乱。
  - 定下来的分工：**热力图图例给"我的"总账，标题行只放主指标（连续打卡天数）+ 入口**。要做"全家"对比时，改成在同一处并列（例如图例里写「我 4 张 · 全家 5 张」），而不是另起一行。

- **二级页的返回目标跟着来源走，不写死**（2026-10-12，用户报"打卡墙怎么是返回厨房，要返回上一级我的"）：
  - 病灶：`/checkins` 写死 `to="/kitchen"`，但它有多个入口（「我的」的打卡块、点单卡上的成品照），从别的入口进来点返回就落到不相干的地方。
  - 做法与家庭页一致：入口带 `state={{ from: '/mine' }}`，页面用一张 `WALL_ENTRIES` 这样的映射表决定文案与目标（`/mine`→返回我的、`/order`→返回点菜单、`/kitchen`→返回厨房），**没带来源时兜底到主要入口**。多入口的二级页一律照此办理，别写死。
  - 配套要求：每个入口一条用例（含"没带来源"的兜底），并验证"写死回某一个固定页"会红。
- **"还没数据"的行不要从列表里删掉，也不要编内容**（2026-10-12，M4 今日安排定）：
  - 厨房页今日安排一开始用的是 M0 的示例数据（「早餐：小米南瓜粥 · 水煮蛋」）——**那是编的菜名**，接真实点单后如果保留，用户根本分不清哪些是真的。
  - 现在的做法：两餐都占一行，没点菜的那行写「还没人点」，**`dishes` 是空数组、不写任何菜名**；行状态 `none` 用中性灰，不用"进行中"的颜色催人。
  - 更泛的一条：**接口返回 0 条不等于可以省略**。首页那种"一眼看全局"的地方，缺行比空行更让人困惑（"晚饭那一行呢？"）。什么时候可以省行，得有明确理由（比如状态筛选的胶囊徽标，0 就不占位置——但那是筛选控件，不是概览）。
- **数值型设置的"未设定"用可空，不要用 0 当哨兵**（2026-10-12，就餐人数定）：
  - `dinerCount` 存 `null` = 还没定；接口传 `null`/空 = 清除设定；`0` 直接 400。
  - 理由：0 在某处一定会被当成"0 个人吃饭"来显示或参与计算（界面写「0 人吃」、平均数除出 `Infinity`），而它真实想表达的是"没填"。可空列 + 显式清除按钮比 0 哨兵少一整类解释成本。
- **加减控件的 onClick 用函数式更新（`setValue(prev => …)`）**（2026-10-12，就餐人数抽屉）：
  - 写 `setValue(String(parsed + 1))` 时，React 会把同一批里的两次点击合成一次渲染，**第二次读到的是上一次的闭包值 → 少加一次**。真机上手快连点就是这个形状。
  - 配套要求：这条的测试**必须把两次点击放进同一个 `act()`**。用 `fireEvent` 分开点则会每次 flush，闭包值已经更新，测试假绿（我第一版就是这样，反证时没变红才发现）。
    **教训：反证没红不等于 bug 不存在，也可能是测试写错了。**
