采购清单放哪儿 · 发现页怎么收

三个方案的差别只有一条：采购清单的新家。共同动作都一样——发现页只留内容、入口回到用它的地方、撤掉写死的假数字。底部 5 个 Tab 的结构不动。

为什么现在要动：发现页上挂了 5 个入口胶囊（收藏 / 点菜 / 常用组合 / 备菜计划 / 去点菜单）和 3 个写死的假数字；而真正每天要用的采购清单，藏在「备菜计划」里一行小字里——三步才够得着。

左右滑动看三屏：发现页 / 冰箱页 / 备菜计划（采购清单现在藏在这里）。

现状的四处毛病（你指出的「乱」）

  • 发现页挂满了入口：收藏、点菜、常用组合、备菜计划、去点菜单——5 个胶囊挤在两张卡的标题行上。入口不是内容，却占着最显眼的位置。
  • 「收藏」从「家人最爱」进去读不通：收藏是私人的，家人最爱是全家榜单；两者没有关系，只是刚好放在一起。
  • 假数字：发现页「85 私房菜 / 12 冰箱食材 / 3 临期」与冰箱页整页示例数据（12 在库 / 3 临期 / 今日先吃）都是 M0 写死的，用户会当真（库内实际 600 道；冰箱功能还没做）。
  • 采购清单埋在三层里：发现 → 备菜计划 → 一行小字，而且它每天买菜都要用一次。

方案 A：采购清单进「冰箱」Tab 第一屏 推荐

买与存是一件事的两半：要买什么 ↔ 家里有什么。做成"只买缺的"（F7-02）、"买完一键入库"（F7-05）都建立在这个配对之上。冰箱 Tab 现在本来就没有真内容，正好把这块真实的放进去，顺手把整页假数据撤掉。

  • 代价：改动面最大（要重做冰箱页这一屏）。
  • 好处：离手最近（底部 Tab 一层，点开就是）；冰箱页从"假的空页"变成"每天都会用的一页"。

左右滑动看三屏：冰箱页（新）/ 发现页（收干净）/ 采购清单卡在四种状态下的样子。

方案 B：采购清单放「厨房」首页

厨房是打开 App 的第一屏，放一条窄入口，最显眼、改动最小（只加一行）。

  • 代价：厨房已经是最挤的一屏（搜索、分类、快捷行、今日安排、推荐 6 张卡）——再加一块，这一屏就更长了。
  • 代价：冰箱页不动，整页假数据继续留着（要另开一刀去清）。

左右滑动看两屏：厨房页（加窄条）/ 发现页（同样收干净）。

方案 C：采购清单放「订单」Tab 顶部

清单是从点单推出来的，放在订单页顶部，与"这些餐现在到哪一步"同屏。

  • 代价：订单页已经有三段控件、状态筛选、卡片流；顶部再插一行，注意力会被分掉。
  • 代价：清单主要按「接下来几天排的菜」算，与备菜计划的动线更近（订单页更偏"现在这一顿的状态流转"）。
  • 冰箱页同样不动，假数据继续留着。

左右滑动看两屏：订单页（加一行）/ 发现页（同样收干净）。

三个方案都要做的共同动作

  • 撤掉假数字：发现页那三格（85 / 12 / 3）直接删——它不是内容，是拼版面用的。冰箱页的假数据只有方案 A 会一并清掉，B / C 要另开一刀。
  • 「收藏」入口只留「我的」（我的页那条已经在），外加每张菜卡右上角那颗心本身。收藏是私人功能，不放在"家人最爱"旁边。
  • 点菜入口不再从发现页重复给：订单 Tab、菜谱小书、每张卡的「点这道」、详情页「想吃这道」已经够了。
  • 「常用组合」与「备菜计划」留在「本周菜单」卡上：它们是排菜工具，跟着这张卡走读得通。（如果你觉得也该挪走，说一声，我把「常用组合」挪到备菜计划页。）
  • 备菜计划里那行「看要买什么 →」保留：排完菜顺路买菜，是同一件事的两半。
  • 底部 5 个 Tab 不动，也不改名。
